# Mandatory Agent Self-Check Specification (10-Point Pre-Done Audit)

این سند مشخصات فنی «سیستم خودبازرسی اجباری ایجنت‌ها (Agent Self-Check System)» را تعریف می‌کند تا هیچ تسکی پیش از تایید ۱۰۰٪ چک‌لیست ۱۰ گانه خودبازرسی، مجاز به انتقال به وضعیت `DONE` یا اعلام پایان کار به کاربر نباشد.

---

## 📋 ۱. چک‌لیست ۱۰ گانه خودبازرسی (The 10-Point Self-Review Audit)

قبل از تغییر وضعیت ماشین حالت به `DONE`، ایجنت لید و ایجنت‌های مجری موظف به تایید موردموردی ۱۰ شرط زیر هستند:

```markdown
### 🛡 Agent Self-Review Checklist
- [ ] Requirement understood? (آیا نیازمندی کاربر و هدف اصلی تسک کاملاً درک شده است؟)
- [ ] All acceptance criteria satisfied? (آیا تمام معیارهای پذیرش به صورت صریح [x] شده‌اند؟)
- [ ] Architecture respected? (آیا معماری کلین، تفکیک لایه‌ها، اصول SOLID و DI رعایت شده‌اند؟)
- [ ] Existing conventions respected? (آیا سیستم طراحی، تم، مسیردهی و استانداردهای نام‌گذاری رعایت شده‌اند؟)
- [ ] No unnecessary files changed? (آیا از ویرایش فایل‌های غیرمرتبط خودداری شده است؟)
- [ ] No user changes overwritten? (آیا کدهای دست‌نوشته کاربر به صورت ناخواسته بازنویسی نشده‌اند؟)
- [ ] Analyze passes? (آیا لینتر و ابزار تحلیل استاتیک استک بدون هیچ خطا و warning پاس شد؟)
- [ ] Targeted tests pass? (آیا تست‌های هدفمند و متناسب با تسک جاری، بدون اجرای کورکورانه کل تست‌های قدیمی و با توقف بلافاصله پس از پاس شدن، با ۰ خطا تایید شدند؟)
- [ ] Zero side-effects & clean scratch? (آیا تست‌ها فاقد فراخوانی سرویس‌های واقعی مانند ایمیل/پیامک بوده و اسکریپت‌های موقت scratch پاکسازی یا به test/ با ماک منتقل شدند؟)
- [ ] Diff reviewed? (آیا گیت‌دیف تغییرات بررسی و تایید گردید؟)
```

---

## 🚫 ۲. قانون انسداد وضعیت DONE (Strict Blocking Condition)

```mermaid
graph TD
    Audit[اجرای چک‌لیست ۱۰ گانه Self-Review] --> Check{آیا تمامی ۱۰ مورد [x] هستند؟}
    Check -->|❌ خیر - حداقل ۱ مورد پاس نشد| Block[🚫 انسداد ترانزیشن DONE / بازگشت به FIXING]
    Check -->|✅ بله - ۱۰ مورد ۱۰۰٪ تایید شدند| Transition[🟢 ترانزیشن به DONE / ثبت در حافظه و تحویل به کاربر]
```

- **اگر حتی ۱ مورد از ۱۰ مورد بالا fail شود**: ترانزیشن به `DONE` **اکیداً ممنوع** است. تسک به وضعیت `FIXING` یا `DIAGNOSING` بازمی‌گردد.
