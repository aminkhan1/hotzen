# Database Mock & Test Isolation Specification

این سند مشخصات فنی «زیرساخت ماک‌سازی و ایزولاسیون دیتابیس در محیط تست (Database Mock & Test Isolation Infrastructure)» را تعریف می‌کند تا ایجنت دیتابیس و ایجنت تستر بدون وابستگی به دیتابیس لایو، لایه‌های ذخیره‌سازی و مخازن داده را تست و اعتبارسنجی نمایند.

---

## 🛠 ۱. الگوی ایزولاسیون و ماک‌سازی داده‌ها در تست

در تمامی پشته‌های نرم‌افزاری، تست‌های دیتابیس و Data Source باید بر اساس یکی از ۳ الگوی ایزوله زیر پیاده‌سازی شوند:

```text
┌────────────────────────────────────────────────────────────────────────┐
│                   Database Test Isolation Patterns                     │
├────────────────────────────────────────────────────────────────────────┤
│ 1. Mock / Stub Interfaces: شبیه‌سازی Contract مخزن با Mockito / Vitest  │
│ 2. In-Memory Database: استفاده از SQLite In-Memory یا Fake Repository  │
│ 3. Test Containers / Temp DB: دیتابیس موقت اختصاصی برای تست‌های یکپارچه│
└────────────────────────────────────────────────────────────────────────┘
```

---

## ⚙️ ۲. پروتکل اجرای تست‌های ایزوله دیتابیس

1. **استفاده از Contract / Interface**: هرگز منطق برنامه نباید به پیاده‌سازی عینی دیتابیس گره بخورد؛ تمامی تعاملات از طریق Interface صورت می‌پذیرد.
2. **عدم آلودگی دیتابیس توسعه/اصلی**: تست‌ها هرگز نباید روی فایل‌های دیتابیس اصلی پروژه یا سرورهای مشترک اجرا شوند.
3. **تست آفلاین و خودکفا (Hermetic Tests)**: هر تست باید محیط دیتابیس/کش خود را در `beforeEach` یا `setUp` مقداردهی اولیه کرده و در `tearDown` پاک‌سازی نماید.
