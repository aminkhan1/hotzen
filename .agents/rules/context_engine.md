# Context Engine & Priority Budgeting Specification

این سند مشخصات فنی «موتور هوشمند کانتکست همراه با مدیریت بودجه و اولویت‌بندی کانتکست (Context Budget & Priority Pruning)» را تعریف می‌کند تا علاوه بر استخراج گراف حداقل مرتبط، حجم کانتکست ارسالی در سقف بودجه توکن تعیین‌شده (Token Budget) کنترل و هرس (Prune) گردد.

---

## ⚡ ۱. ابعاد ۱۱ گانه کانتکست (The 11 Context Dimensions)

1. **User Context**: نیازمندی صریح و دستور کاربر.
2. **Task Context**: وضعیت فعلی تسک در ماشین حالت.
3. **Project Context**: استانداردهای ثابت و ساختار فولدرها.
4. **Architecture Context**: مرزهای معماری و الگوی مدیریت وضعیت موجود در Stack جاری، در صورت وجود.
5. **File Context**: مسیر دقیق فایل‌های لودشده.
6. **Symbol Context**: تعاریف نمادها و کلاس‌ها.
7. **Dependency Context**: وابستگی‌های بالا به پایین و پایین به بالا.
8. **Git Context**: گیت‌دیف تغییرات درگیر.
9. **Runtime Context**: لاگ خطاهای زمان اجرا.
10. **Test Context**: سوئیت و لاگ تست‌های مرتبط.
11. **Agent Context**: نقش ایجنت تخصصی مجری.

## 🎯 ۲. ماتریکس اولویت‌بندی بودجه کانتکست (Context Priority Matrix)

هنگامی که حجم کانتکست استخراج‌شده از بودجه مجاز (مثلاً ۱۲,۰۰۰ توکن برای کانتکست پویا) فراتر رود، هرس بر اساس ماتریکس اولویت زیر از پایین‌ترین اولویت انجام می‌شود:

```text
================================================================================
                    CONTEXT PRIORITY & BUDGET MATRIX
================================================================================
[Priority 100]  Current File(s) & Target Slice
               ➔ فایل اصلی و برش دقیقی که ویرایش می‌شود (هرگز هرس نمی‌شود)

[Priority 90]   Direct Dependencies
               ➔ وابستگی‌های مستقیم (کلاس‌ها و اینترفیس‌هایی که مستقیم صدا زده شده‌اند)

[Priority 80]   Direct Dependents
               ➔ کامپوننت‌های مستقیم وابسته (کلاس‌هایی که فایل اصلی را صدا می‌زنند)

[Priority 70]   Relevant Tests
               ➔ تست‌های واحد، یکپارچگی یا رابط کاربری مستقیم مرتبط با تغییر و متناسب با Stack جاری

[Priority 50]   Architecture & Core Context Slice
               ➔ برش کانتکست معماری و قوانین Core

[Priority 20]   Unrelated / Distant Project Context
               ➔ سایر بخش‌های عمومی و نامرتبط پروژه (اولین لایه‌ای که هرس می‌شود)
================================================================================
```

## 🛑 ۴. شروط توقف حلقه دینامیک کانتکست (Context Loop Stop Conditions)

موتور کانتکست گسترش پویا را طبق [context_loop.md](.agents/rules/context_loop.md) به محض وقوع یکی از شروط ۴ گانه متوقف می‌کند:
1. رفع کامل تمامی وابستگی‌های غیرشفاف (`No Unresolved Dependency`).
2. عدم تغییر در فرضیه یا تصمیم معماری با شواهد جدید (`No Decision Change`).
3. پوشش کامل داده‌های لازم برای اعتبارسنجی معیارهای پذیرش (`Acceptance Criteria Supported`).
4. وصول به سقف بودجه توکن تعیین‌شده (`Context Budget Limit Reached`).
